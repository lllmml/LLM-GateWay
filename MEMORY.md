## Decisions

- 2026-09-08 (Week 8, ADR-017): Reliability baseline. One overall upstream phase budget per request (`UpstreamRequestTimeout`/`UpstreamStreamMaxDuration` from phase start, min downstream ctx) is shared by attempts and backoff - retries never multiply the timeout and no new timeout config was added. retryCount is in-memory only (row created once, finalized once with the final count); boundary is `retryCount >= maxRetries` (retries after the initial attempt, 0-5, config default 1, 0 disables). Retry whitelist never keys on category alone: provider 429 (status 429), provider 5xx (status >= 500, structurally excluding 401/402/403), and dial/DNS transport failures only; never ProviderTimeout/4xx/StreamInterrupted/unknown errors/cancellation. Streaming retry stops the instant `StreamChat` returns a `ChatStream` (provider may already be billing) even before the first committed byte; established-stream failures keep stream_interrupted semantics. Retry-After is presence-preserving `*time.Duration` (nil = no hint, present 0 = retry now); adapters parse via `provider.ParseRetryAfter`, executor decides; a terminal un-retried provider 429 writes a gateway-computed `Retry-After` header - no raw provider headers leak. Bucket: `golang.org/x/time/rate` v0.15.0, refill N/min, burst = N (gateway policy, not an x/time default); two-scope admission locks key entry then project entry and reserves both with one `now` (`DelayFrom`, never `Delay`) then commits both or cancels both - no quota leakage under concurrency. Registry is bounded: janitor sweeps idle entries past `RATE_LIMITER_IDLE_TTL`, `RATE_LIMITER_ENTRY_CAP` evicts LRU (documented full-burst reset window), `Close()` stops the janitor. Rate-limit/concurrency rejections precede any provider call and any durable row: HTTP 429 `rate_limited`, no PostgreSQL writes; provider 429 after exhausted retries stays `provider_rate_limited` (categories never merged). Concurrency: general slot for all requests, streams additionally need a stream slot, non-blocking reject, deferred exactly-once release, stream-cap failure releases the general slot first. Config defaults: rate limits/caps 0 = disabled (`.env.example` shows values); retries default 1. Circuit breaker still deferred with recorded re-evaluation triggers.

- 2026-09-05 (Week 7, ADR-016): Estimated cost = BASE-RATE ESTIMATE in integer nano-USD (`internal/pricing`): floor division per direction, overflow-checked; never an invoice. `pricing_id` is provenance and `estimated_cost` is derived - no iff invariant and no DB CHECK: no price -> both NULL; price found + usage + ok -> pricing_id + cost; price found + usage missing or calc failure -> pricing_id + NULL cost; failed requests are never priced. Price lookup uses `request.started_at` against the half-open window `effective_from <= started_at < effective_to` (NULL = still in force); overlap is a catalog data-quality error resolved deterministically to the newest effective version, and a catalog validator integration test asserts the seed is overlap-free. Pricing lookup/calc problems degrade to NULL plus a bounded log line and never fail a gateway request.

DeepSeek 2026 pricing splits cache hit/miss and peak/off-peak while the schema persists only prompt/completion/total tokens; no DeepSeek price version is seeded and requests record usage with `pricing_id`/`estimated_cost` NULL. Cache/time-tier-aware exact pricing is a later iteration requiring adapter + schema changes; nothing is changed this week to force it.

- 2026-09-04: Week 6 adds an optional integer `max_tokens` to the public OpenAI-compatible subset (approved Option 1): `internal/dataplane` decode accepts a positive value and keeps it off the wire when absent; OpenAI/DeepSeek forward it unchanged when present; Anthropic maps it onto its required `max_tokens` and applies a documented gateway default of `4096` (`defaultMaxTokens`) when the client omits it. `max_tokens <= 0` is rejected before any upstream work.
- 2026-09-04: The Anthropic adapter (`internal/provider/anthropic`) is deliberately independent of `oaiwire`: it posts to `/v1/messages` on `https://api.anthropic.com`, authenticates with `x-api-key` plus the required `anthropic-version: 2023-06-01` (no `Authorization`), translates only **leading** system messages (before the first user/assistant message) into the top-level `system` field (`"\n\n"`-joined), and captures the documented `request-id` response header. Contract facts were verified against the official Messages/Streaming/Errors docs and the anthropic-sdk-typescript source fetched 2026-09 (matrix: `docs/provider-capabilities.md`).
- 2026-09-04: Anthropic streaming requires a bidirectional translation, unlike the OpenAI/DeepSeek byte passthrough: the adapter re-encodes `content_block_delta` text into OpenAI-compatible chunk envelopes, maps `stop_reason` onto OpenAI finish reasons (end_turn→stop, max_tokens/model_context_window_exceeded→length, stop_sequence→stop, tool_use→tool_calls, refusal→content_filter, pause_turn and unknown→""), synthesizes `object`/`created` (Anthropic does not report them), and emits a synthetic `data: [DONE]` only at a valid `message_stop`. Usage is committed only at `[DONE]`: `input_tokens` from `message_start`, cumulative `output_tokens` seeded by the `message_start` baseline and advanced by `message_delta`; `total_tokens` is computed (Anthropic reports no total).
- 2026-09-04 (Week 6 review 1): Anthropic adapter correctness fixes. (1) Mid-conversation `system` messages are no longer silently hoisted: only leading system messages go to the top-level `system` field, and a system message after the first user/assistant turn is rejected with `unsupported_feature` in `buildRequest` before any upstream HTTP work (data plane returns HTTP 400 `unsupported_feature` and finalizes the durable record as failed). (2) The Anthropic SSE state machine now tracks an explicit phase (initial/started/finalized): `message_start` exactly once and first, no `message_delta`/`message_stop` before `message_start`, content only between `message_start` and the first `message_delta`, and `message_stop` accepted only after at least one `message_delta`; malformed sequences fail as `stream_interrupted` with no synthesized `[DONE]` and no exposed/persisted usage. Usage counters must be non-negative, and `message_delta.output_tokens` (cumulative) must never decrease. (3) Anthropic `refusal` maps to OpenAI finish reason `content_filter` in both non-streaming and streaming normalization; `pause_turn` stays outside the supported subset and normalizes to `""`.
- 2026-09-04 (Week 6 review 2): Anthropic adapter presence/ordering corrections. (1) Stream usage fields must be explicitly present: `message_start` requires a `usage` object with `input_tokens`, and every `message_delta` requires a `usage` object with `output_tokens`; wire parsing uses pointer fields so a missing counter is rejected (`stream_interrupted`) instead of silently decoding to zero, while an explicit zero remains valid (non-negative enforced). (2) `content_block_start`/`content_block_stop` before `message_start` are rejected as `stream_interrupted`; `ping` and unknown named events remain tolerated/skipped. (3) Rationale for the mid-conversation `system` rejection corrected: Anthropic supports mid-conversation `role:"system"` on some models but not all; the Week 6 gateway subset intentionally does not implement per-model capability detection, so the adapter conservatively rejects before upstream work (revisitable with provider/model capability negotiation). Client wording for adapter-generated `UnsupportedFeature` is now "request includes a feature not supported by the gateway for the selected provider" (never Anthropic internals).
- 2026-09-04 (Week 6 review 3): Anthropic stream-state final pass. (1) `message_start.message.usage.output_tokens` is now required (present and non-negative) and seeds the cumulative output baseline, so a later `message_delta.usage.output_tokens` below that baseline is rejected as `stream_interrupted`; the persisted completion count still comes from the latest cumulative value. (2) Known content-block boundary events (`content_block_start`/`content_block_stop`) are allowed only during the started phase: rejected before `message_start` and after the first `message_delta` (no per-block lifecycle/index tracking); `ping` and unknown named events remain tolerated/skipped.
- 2026-09-04: Anthropic differences kept explicit in the adapter: unknown named SSE events and non-text deltas (thinking/signature/input_json) are skipped gracefully per Anthropic's versioning policy, while a bare data frame without an event name fails loudly; `event: error` mid-stream classifies by `error.type` (overloaded/api/auth → provider_unavailable, rate_limit → provider_rate_limited). HTTP status mapping is adapter-owned: 400/404/409/413 → provider_invalid_request; 429 → provider_rate_limited; 504/408 → provider_timeout; 401/402/403 and 500/529 → provider_unavailable (server-side conditions never surface as client 400).
- 2026-09-04: Anthropic `content` is an array of blocks; only `type:"text"` blocks are forwarded (joined without a separator so non-stream equals a stream of text deltas). Non-text blocks never appear because the gateway subset does not request tools/thinking; thinking is intentionally not forwarded, consistent with the DeepSeek `reasoning_content` handling.
